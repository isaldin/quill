# Quill — синхронизация настроек и профилей

Дата: 2026-10-14
Статус: на ревью
Дополняет: `2026-10-14-quill-design.md` (раздел 10 «Не входит в v1» — синхронизация между машинами)

## 1. Цель

Одинаковые настройки и профили на всех ноутбуках пользователя без ручного переноса.
Все ноутбуки — macOS с одним Apple ID и включённым iCloud Drive.

### Критерии готовности

- Профиль, созданный или изменённый на одном ноутбуке, появляется на другом без перезапуска приложения.
- Модели по умолчанию и прочие общие настройки, изменённые на одном ноутбуке, применяются на другом.
- Ключ OpenRouter не хранится в облаке. На новом ноутбуке его вставляют один раз.
- Существующие настройки и профили переезжают сами, ничего не теряется.

### Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Механизм | Обычная папка в iCloud Drive; файлы читаются и пишутся напрямую. iCloud API (CloudKit, iCloud Keychain) не используются: им нужен платный аккаунт разработчика, а сборки подписываются Personal Team |
| Ключ OpenRouter | В Keychain каждой машины (как сейчас). В настройках появляются «Показать», «Скопировать» и ссылка на создание ключа |
| Конфликты | Выигрывает последняя запись `settings.json`; конфликтные копии iCloud игнорируются |

## 2. Что где хранится

### Общая папка

1. Если существует `~/Library/Mobile Documents/com~apple~CloudDocs/`, общая папка — `~/Library/Mobile Documents/com~apple~CloudDocs/Quill/` (в Finder: «iCloud Drive → Quill»).
2. Иначе — `~/.config/quill/` (синхронизации нет, в настройках видно «Синхронизация выключена: iCloud Drive недоступен»).

Папка выбирается при запуске приложения.

Содержимое общей папки:

| Путь | Что |
|---|---|
| `settings.json` | Общие настройки |
| `profiles/*.md` | Профили, формат прежний |

### `settings.json`

```json
{
  "version": 1,
  "default_transcription_model": "openai/gpt-4o-transcribe",
  "default_llm_model": "openai/gpt-4.1-mini",
  "audio_limit_gb": 1.0,
  "sounds_enabled": true,
  "show_indicator": true
}
```

Разбор терпимый: отсутствующее поле получает значение по умолчанию (указаны выше), неизвестные поля игнорируются.
Значение неверного типа (например, строка вместо числа) делает файл битым (раздел 4).
Пустые строки в моделях заменяются значениями по умолчанию; `audio_limit_gb` меньше 0.1 считается равным 0.1.

### Локально на каждой машине (без изменений)

| Что | Где |
|---|---|
| Ключ OpenRouter | Keychain |
| Микрофон, «запускать при входе», горячие клавиши | `UserDefaults` / `SMAppService` / KeyboardShortcuts |
| Активный профиль | `UserDefaults` (`activeProfileID`) — на разных ноутбуках обычно разные проекты |
| История и аудио | `~/Library/Application Support/Quill/` |

## 3. Переезд при первом запуске

Выполняется при каждом запуске, но меняет что-то только если в общей папке чего-то нет:

1. Создать общую папку и `profiles/`, если их нет.
2. Если нет `settings.json`, записать его из первого доступного источника:
   1. `~/.config/quill/settings.json`, если общая папка — iCloud и такой файл есть;
   2. текущие значения в `UserDefaults` (ключи `defaultTranscriptionModel`, `defaultLLMModel`, `audioLimitGB`, `soundsEnabled`, `showIndicator`);
   3. значения по умолчанию.
3. Если в `profiles/` нет ни одного `.md`, скопировать туда `*.md` из `~/.config/quill/profiles/`, если общая папка — iCloud и такие файлы есть. Исходные файлы не удаляются.
4. Если `profiles/` по-прежнему пуст, `ProfileStore.bootstrap()` создаёт встроенные `raw.md` и `clean.md` (как сейчас).

Существующие файлы в общей папке никогда не перезаписываются переездом.

## 4. Поведение

### Чтение

- `SharedSettingsStore` следит за общей папкой (DispatchSource, как `ProfileStore`) и перечитывает `settings.json` при изменении.
- Дополнительно `settings.json` и профили перечитываются перед каждой записью диктовки и при открытии окна настроек.
- Читается только файл с именем ровно `settings.json`. Конфликтные копии iCloud (`settings 2.json` и подобные) игнорируются.
- Конфликтные копии профилей (`work 2.md`) ничем не отличаются от обычных файлов и показываются в меню отдельными профилями (`work 2`). Какую версию оставить, пользователь решает сам.

### Запись

- Изменение общей настройки в окне настроек сразу записывает весь `settings.json` атомарно (временный файл в той же папке + переименование).
- Текстовые поля моделей записываются по Enter или при потере фокуса, а не на каждый символ.

### Файл ещё не скачан из iCloud

Если вместо `settings.json` лежит заглушка `.settings.json.icloud`, вызывается `FileManager.startDownloadingUbiquitousItem(at:)` для `settings.json`, а до прихода файла используются последние известные значения (при первом запуске — значения из переезда или по умолчанию). Переезд в этом случае `settings.json` не создаёт: файл уже есть в облаке.

То же для профилей: для каждой заглушки `.<имя>.md.icloud` запрашивается скачивание; профиль появится в меню после прихода файла.

### Битый `settings.json`

- Приложение продолжает работать на последних корректных значениях (при первом запуске — значения по умолчанию).
- В окне настроек показывается предупреждение с текстом ошибки разбора.
- Файл не перезаписывается автоматически. Первое изменение настройки в окне записывает полный корректный файл.

### Ключ OpenRouter в настройках

- «Показать» переключает поле ключа между скрытым и открытым видом.
- «Скопировать» кладёт ключ в буфер обмена.
- Ссылка «Создать ключ на OpenRouter» открывает `https://openrouter.ai/settings/keys`.

### Секция «Синхронизация» в настройках

- Где лежат общие файлы (iCloud Drive или `~/.config/quill`) и кнопка «Открыть папку».
- Предупреждение о битом `settings.json`, если есть.

## 5. Компоненты

| Компонент | Где | Ответственность |
|---|---|---|
| `SharedSettings` | Core | Структура общих настроек, значения по умолчанию, терпимый разбор и кодирование JSON |
| `SharedSettingsStore` | Core | `@MainActor @Observable`: текущие значения, ошибка разбора, `reload()`, `update(_:)` с атомарной записью, наблюдение за папкой, запрос скачивания заглушки |
| `SyncLocation` | Core | Выбор общей папки по наличию iCloud Drive (корень передаётся параметром для тестов) |
| `SyncBootstrap` | Core | Переезд из раздела 3; источники передаются параметрами |
| `AppSettings` | App | Общие поля читает и пишет через `SharedSettingsStore`, локальные — через `UserDefaults` |
| `ProfileStore` | Core | Без изменений API; получает каталог `profiles/` общей папки; дополнительно запрашивает скачивание заглушек `.icloud` |

## 6. Тестирование

Модульные тесты (XCTest, временные папки вместо iCloud):

- `SharedSettings`: полный файл; отсутствующие поля → значения по умолчанию; неизвестные поля игнорируются; пустая строка модели → значение по умолчанию; `audio_limit_gb` < 0.1 → 0.1; неверный тип и битый JSON → ошибка.
- `SharedSettingsStore`: запись и чтение; атомарная запись не оставляет временных файлов; битый файл сохраняет последние значения и выставляет ошибку; после `update` файл корректен и ошибка снята; `settings 2.json` игнорируется; заглушка `.settings.json.icloud` без самого файла не сбрасывает значения.
- `SyncLocation`: с корнем iCloud и без него.
- `SyncBootstrap`: `settings.json` из `~/.config` → из `UserDefaults` → по умолчанию; существующий `settings.json` не трогается; при заглушке `settings.json` не создаётся; профили копируются только в пустую папку и только из iCloud-режима; исходные профили остаются.

Вручную (пункты в README):

- первый запуск переносит текущие модели и профили в «iCloud Drive → Quill»;
- второй ноутбук после установки получает те же профили и модели;
- изменение профиля и модели на одном ноутбуке видно на другом без перезапуска;
- «Показать» и «Скопировать» ключа работают.

## 7. Не входит

- Синхронизация ключа OpenRouter.
- Синхронизация истории и аудио.
- Слияние одновременных правок (выигрывает последняя запись).
- Синхронизация без iCloud Drive (git, Dropbox и т. п.).
